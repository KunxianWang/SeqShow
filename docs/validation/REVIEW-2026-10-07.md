## 范围与发现

已检查 Parser、Model、纯 Playback、Mermaid 适配、共享播放器、导出以及现有测试和构建配置。以下均为现有 M0–M2 行为的修复，不推进 M3–M5。

| 级别 | 问题与复现 | 修复 |
| --- | --- | --- |
| P2 | `alt ->> B: hello`、`else -->> B: hello` 使用合法参与者 ID，却被当成 alt/else 控制语句；真实分支内也失败 | 在识别控制语句前匹配完整消息，保留空格/制表符和两种箭头的语义 |
| P2 | `A->>B: one; activate B`、`one; loop retry` 等拼接输入被当成一条普通消息，绕过不支持语法诊断 | 分号后的关键字检查复用不支持语句清单，仍返回分号所在行列 |
| P2 | 普通文本 `one; optional; loop-count; title=value; https://example.com:80/x` 被跨越分号、扫描到后续 URL 冒号的正则误拒绝 | 第二条消息须有箭头、接收者和语法冒号，普通分号、关键字前缀与 URL 保持为文本 |
| P2 | `A->>B:`、仅含空白的消息、自调用及 Note 能通过 Parser，但渲染时报文本映射错误 | Mermaid 12.1.0 对空标签生成一个 U+200B；仅在模型文本为空白时接受该占位符，不全局删除零宽字符或跳过非空文本校验 |

回归先证明错误：原 Parser 的 22 个新增用例失败；普通分号文本另有独立失败；新增空标签浏览器 fixture 在适配器修复前报 `SVG message text mismatch`。分号诊断测试中列号的手写期望曾少算一列，已按原始输入修正为第 13 列。

新增两个真实 Parser→SVG→离线 fixture：关键字参与者（含中英文标签和两条分支）与空标签（消息、自调用、四种 Note）。路径期望独立手写。
