## 发现并修复的问题

20 个参与者、200 条消息、10 个 alt 的长标签图，原始源码只有 46,085 UTF-16 单位，Parser 正常接收，但内部参与者 ID、折行标记与实体编码让序列化输入超出 Mermaid 的默认 50,000 字符。Mermaid 返回一个错误 flowchart；安全检查正确拒绝其中的 foreignObject，用户因此看见渲染失败。

适配层现在先序列化，使用该生成输入的实际长度配置 maxTextSize，再渲染。原始源码仍由 Parser 的 50,000 上限约束，没有放宽输入语法、原始限额、strict 安全配置或 SVG 白名单。默认限额见 [Mermaid 官方 maxTextSize 说明](https://mermaid.js.org/config/schema-docs/config-properties-maxtextsize.html)，替换错误图的行为已在锁定版本本地源码核实。

新 production 用例同时达到四项上限：50,000 UTF-16、20 个参与者、200 条 Message、10 个 alt，包含大量中文、&、;、#；注释补足源码到准确边界。验证成功 Render、100 步所选路径、10 个选择器、换路径后的正确消息、稳定 SVG 几何、无 foreignObject，以及可导出。代码见 [editor.spec.ts](../../tests/e2e/editor.spec.ts) 中 `supported input at all four limits`。

| 8,085 | 293 ms | 252 ms | 33 / 37 ms | 13,285 |
| 46,085 | 1,565 ms | 146 ms | 138 / 252 ms | 52,385 |

测量包含 Playwright 操作及浏览器布局开销，单次本机采样，没有 CPU/网络限速，不是渲染器纯函数基准或跨设备速度保证。此时最大长图每次切步仍有可感知成本，后续如出现真实性能反馈再定位，不提前引入虚拟布局或另一个渲染器。

两图都逐步到 100/100、切换最后一个 alt 后回总览，viewBox 不变，全页无横向溢出；真实导出在全新 Chromium 离线上下文打开，保留最后一个 alt 的第二条选择并可 Next，远程资源请求尝试为 0。产物为 artifacts/m5/ceiling-20.html 和 ceiling-210.html，测量详情为 manual-qa.json。
